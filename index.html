FunGen-xQTL Computational Protocol

Reproducible, reusable pipelines for molecular QTL analysis, developed for the NIH/NIA Alzheimer’s Disease Sequencing Project (ADSP) Functional Genomics xQTL (FunGen-xQTL) project. A molecular QTL (xQTL) is a genetic variant linked to a change in a molecular trait, such as gene expression, splicing, protein level or DNA methylation.

Where do you want to start?¶

Try the example data

Install the software, then run your first module on the small example data that comes with the repository.

Find the pipelines you need

Answer a few questions about your data and goals. Get the modules on your route and the commands to run them.

Use your own data

File formats, sample IDs and checks for each input, so your files work the first time.

Run on a cluster

Set up SLURM or SGE once, then send any command’s jobs to your cluster.

What the protocol covers¶

StageWhat it does
Reference dataPrepare the genome, gene annotation, alignment indices, TAD-based association windows and LD reference
Molecular phenotypesQuantify expression, splicing, methylation and polyadenylation from bulk RNA-seq, single-nuclei or array data
Data preprocessingGenotype QC and formatting, phenotype imputation and formatting, covariate and hidden-factor estimation
QTL association testingcis and trans scans with TensorQTL, quantile-regression QTL, hierarchical multiple testing
Multivariate modelingMASH, to borrow information across tissues and cell types
Fine-mapping and TWASSuSiE, mvSuSiE, fSuSiE and SuSiE-RSS, from individual-level data or summary statistics, with TWAS weights
GWAS integrationColocalization (SuSiE-enloc, ColocBoost), TWAS and cTWAS, INTACT
Enrichment and validationPathway analysis, GREGOR, stratified LD score regression

Not every project needs every stage. The xQTL Analysis Workflow Builder asks what you measured and what you want to find out, then shows the modules on that route with the commands to run them.

Overview of the protocol¶

Standardized reference data¶

The ADSP FGC Standardization Workgroup curates the reference data with NIAGADS. The standardized files and their specifications are on Synapse (syn36416587). Where to get reference data lists each file, its source and the modules that use it.

Software environment¶

We use a set of packages from the Conda ecosystem to deploy our software. Most packages are from conda-forge and bioconda, along with a custom channel for software unavailable from those repositories. Installation is managed through pixi-setup; native support is provided for Linux and macOS (Intel and Apple Silicon), and Windows users will need Windows Subsystem for Linux (WSL).

Pipeline execution¶

Pipelines in this repository are written in the Script of Scripts (SoS) workflow language. Each pipeline is a Jupyter notebook that holds both the explanation and the pipeline code. The same notebook runs as a command-line script with sos run, on a local computer or on a cluster, where SoS submits each task as a job.

To run on a SLURM or SGE cluster, follow Running on a cluster: a one-time setup, then any command on this site can send its jobs to the cluster.

Source code¶

The source code of the pipelines is in the code folder on GitHub.

How to use the resource¶

Organization of the resource¶

This website is generated from files under the code folder of the source code repository. The pipeline folder contains symbolic links automatically generated for pipeline files under code, so analyses are run from the root of the repository by typing sos run pipeline/<pipeline_file>.ipynb.

The left sidebar (the menu button on a narrow screen) follows the order of an xQTL analysis, one analysis stage per entry:

  • Mini-protocols are the pages directly under each stage. Each walks through one analysis step by step, with the commands to run in a terminal or in Jupyter.

  • Pipeline modules are listed under each mini-protocol (open it with the arrow). Each module is a self-contained command-line pipeline that can also be used outside xQTL analysis.

Example data¶

Every module has example data committed under tests/fixtures/, subset to chr22 to keep the repository small. These are the same files the test suite runs against, so the commands shown in the documentation can be run directly after cloning, with no download required. Every path shown resolves either to one of these fixtures or to the output directory of the step that produces it.

Large reference files (genome FASTA, GTF annotations, aligner indices, external LD panels) are not distributed with the repository. Where to get reference data lists their sources and the modules that use them.

How to cite¶

The FunGen-xQTL protocol paper is in preparation. Until it is out, please cite this repository (https://github.com/StatFunGen/xqtl-protocol) and the papers for the methods you use, such as SuSiE, ColocBoost or TensorQTL. Methods and references lists the paper for each method by module.

Get help¶

  • Something not working, or a question about a module: open an issue on GitHub.

  • Include the command you ran, the error message and the output of pixi list if it is about the software environment.
