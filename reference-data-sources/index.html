Where to get reference data

The example data in tests/fixtures/ is enough to run every Minimal Working Example. A full analysis also needs genome-wide reference files, which are too large to keep in the repository. This page lists each one, where it comes from, and which modules use it. All files are GRCh38.

Download, then format with the protocol¶

Reference Data Standardization downloads these files and formats them for the protocol (chromosome names, removed alternate contigs, added ERCC spike-ins). Run its steps rather than using the raw downloads directly.

Standardized copies on the AD Knowledge Portal¶

The ADSP Functional Genomics Consortium keeps the standardized reference files, with their specifications, on the AD Knowledge Portal (syn36416587). Use these to match the consortium’s analyses exactly. The AD Knowledge Portal needs a free account.

LD reference¶

Fine-mapping from summary statistics (RSS fine-mapping), TWAS, cTWAS and MR, ColocBoost with summary statistics and SuSiE-enloc need a linkage disequilibrium (LD) reference: correlations between variants, split into LD blocks. Modules read it through an LD meta file (--ld-meta-data), a table of blocks (#chr, start, end, path).

  • ADSP LD reference panel. LD matrices from whole-genome sequencing of 16,571 non-Hispanic white individuals (Genome Center for Alzheimer’s Disease), computed within 1,361 LD blocks defined from 1000 Genomes EUR samples. Each block is a .cor.xz matrix with a .cor.xz.bim variant list. Controlled access: request ADSP access on the AD Knowledge Portal, then synapse get -r syn53171227. Details on the xQTL Resources LD reference page.

  • Your own panel. Build LD sketches from genotypes with RSS LD sketch. Use this when your GWAS ancestry differs from the ADSP panel.

The example LD meta file is tests/fixtures/ld_reference/ld_meta_file.tsv.
